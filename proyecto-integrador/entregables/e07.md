# E7. Implementación y pruebas

**Sprint 3 · Tema VI.** Fuente: [presentación](../../presentaciones/presentacion-programa-proyecto-si.pdf), p. 19; asignación por sprint: programa p. 2.

## Alcance de la fuente

Versión funcional integrada, pruebas unitarias, de integración, de sistema y registro de defectos.

## Guía de elaboración

Desarrollar esta entrega sobre el proyecto asignado al equipo.

**Insumos:** Diseños E1–E6, entorno Django del equipo, PostgreSQL de prueba, pytest y pytest-django.

1. Integrar los módulos mínimos del proyecto asignado y registrar el commit y las versiones.
2. Preparar datos sintéticos y una BD exclusiva de pruebas.
3. Implementar pruebas unitarias de reglas, de integración de persistencia y de permisos con el cliente Django; usar django_db donde corresponda.
4. Ejecutar python -m pytest y registrar resultados, entorno y defectos reproducibles.
5. Recorrer los flujos completos como pruebas de sistema; comprobar validaciones y permisos. Las pruebas de aceptación pertenecen al tema VI y permiten contrastar requisitos con los usuarios.
6. Corregir defectos y repetir las pruebas afectadas; enlazar los cambios para su documentación en E8.

## Comprobación antes de entregar

La versión integrada reproduce los flujos mínimos y conserva evidencias de pruebas unitarias, de integración y de sistema. La ausencia de pruebas no equivale a una suite aprobada.

## Evidencias del entregable

Commit evaluable, pasos de ejecución y resultados de pruebas con entorno y datos de prueba.

## Criterios de revisión

Flujos mínimos integrados; permisos y validaciones comprobados; defectos reproducibles y seguimiento.

Registrar las evidencias en el repositorio del equipo y enlazar el commit correspondiente.
