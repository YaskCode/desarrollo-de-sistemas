# E6. Diseño de base de datos

**Sprint 3 · Tema V.** Fuente: [presentación](../../presentaciones/presentacion-programa-proyecto-si.pdf), p. 18; asignación por sprint: programa p. 2.

## Qué aprenderás

Traducir el dominio a un modelo de datos coherente y ejecutable.

## Antes de comenzar

Revisar la [unidad correspondiente](../../unidades/05-bases-de-datos/README.md), sus lecturas y los insumos indicados abajo. Retomar los identificadores y decisiones de las entregas anteriores.

## Alcance del entregable

Modelo ER, cardinalidades, normalización hasta 3FN, esquema relacional y scripts SQL. Diccionario de datos BD.

## Material de apoyo

[Apuntes del tema](../../unidades/05-bases-de-datos/apuntes.md) y [ejemplo de estudio](../../unidades/05-bases-de-datos/ejemplo-base-datos.md). El ejemplo es un fragmento hipotético; la entrega debe cubrir el alcance del proyecto asignado.

## Guía de elaboración

Desarrollar esta entrega sobre el proyecto asignado al equipo.

**Insumos:** Requisitos, DFD, diccionario y diseño del sistema; PostgreSQL y pgAdmin.

1. Construir el modelo ER e identificar entidades, cardinalidades y claves del proyecto.
2. Describir dependencias funcionales y justificar la normalización hasta 3FN.
3. Transformar el ER en el esquema relacional y preparar scripts SQL con claves y restricciones.
4. Ejecutar los scripts en una BD local con datos sintéticos; comprobar consultas y rechazo de referencias inválidas.
5. Redactar el diccionario de BD y contrastarlo con el modelo, los scripts y E3.

## Comprueba tu trabajo

- [ ] ER, cardinalidades, claves y esquema relacional son consistentes.
- [ ] La justificación de normalización explica las dependencias hasta 3FN.
- [ ] Los scripts se ejecutan en una BD de prueba y comprueban restricciones.
- [ ] El diccionario de BD corresponde a los scripts y conserva trazabilidad con E3.

Estas comprobaciones ayudan a revisar esta entrega; no son actividades adicionales ni una calificación automática.

## Evidencias del entregable

Modelo editable, justificación de normalización, SQL reproducible y diccionario de tablas/columnas diferenciado del diccionario DFD.

## Error frecuente

Afirmar que el diseño está normalizado sin explicar las dependencias o sin contrastarlo con SQL.

Aplicar las [estrategias transversales](../../docs/enfoques-ingenieria.md) correspondientes a esta entrega: conservar trazabilidad, verificar la evidencia y contrastarla con las necesidades del usuario cuando corresponda. Registrar el resultado dentro de los documentos o pruebas de esta misma entrega.

Cardinalidades y claves consistentes; restricciones verificables; SQL ejecutable en PostgreSQL.
