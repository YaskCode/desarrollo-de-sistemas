# Guía para estudiantes

1. Leer los [documentos fuente](../programa/README.md).
2. Recorrer las [seis unidades](../unidades/README.md) y la [evaluación](evaluacion.md).
3. Consultar la ficha del [proyecto integrador](../proyecto-integrador/proyectos-propuestos.md) asignado por la docente.
4. Seguir la única ruta de trabajo práctico y relacionar cada requisito con sus [entregables](../proyecto-integrador/entregables/README.md).
5. Desarrollar el código en el repositorio de equipo de [YaskCode-laboratory](https://github.com/YaskCode-laboratory).

## Flujo de trabajo complementario propuesto

Crear una issue por tarea, trabajar en una rama y revisar mediante pull request. Registrar en cada entrega el commit evaluable, instrucciones de reproducción y evidencias. Fechas, equipos y aceptación de este flujo se acuerdan con la docente; no se presuponen asignaciones.

Utilizar datos sintéticos; no publicar cédulas, expedientes, credenciales ni datos personales reales. Explicar decisiones y citar fuentes; documentar cualquier asistencia de IA como recomendación de transparencia académica.

## Entorno

[Herramientas](../recursos/herramientas.md) y [guía reproducible de instalación](entorno.md). No se fija una versión arbitraria del curso: cada equipo debe registrar versiones compatibles efectivamente utilizadas y conservar sus dependencias.

## Publicación de materiales

Mantener Markdown con títulos jerárquicos, enlaces descriptivos y texto alternativo en imágenes. Usar enlaces relativos internos y agregar cada nuevo material a su índice. No subir carpetas vacías o enlaces a futuros archivos.
