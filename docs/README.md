# Guía para estudiantes

## Comenzar

1. Consultar el [programa y la presentación](../programa/README.md).
2. Revisar las [seis unidades](../unidades/README.md) y el [plan de evaluación](evaluacion.md).
3. Consultar la ficha del [proyecto integrador](../proyecto-integrador/proyectos-propuestos.md) asignado al equipo.
4. Desarrollar los [entregables E1–E8](../proyecto-integrador/entregables/README.md) en el repositorio del equipo en [YaskCode-laboratory](https://github.com/YaskCode-laboratory).

## Preparar y presentar una entrega

Trabajar en una rama, registrar los cambios con Git y utilizar issues y pull requests para coordinar tareas y revisar aportes. Mantener la documentación de cada entrega dentro del repositorio del equipo.

Para presentar E1–E8, identificar:

- Equipo y proyecto.
- Número y título del entregable.
- Enlace al repositorio y al commit que contiene la versión presentada.
- Enlaces a los documentos y evidencias indicados en la ficha.
- Instrucciones de reproducción cuando la entrega incluya SQL, implementación o pruebas.

Usar enlaces que permitan consultar la versión presentada; un enlace a una rama cambiante no identifica por sí solo esa versión. Consultar en clase las fechas y el canal de recepción de las entregas. No publicar información privada en issues públicas.

## Retroalimentación y correcciones

Revisar los [criterios de cada entrega](../proyecto-integrador/entregables/README.md) antes de presentarla. Conservar el commit original y registrar las correcciones en nuevos commits; relacionar cada cambio con la observación atendida. La recepción y evaluación corresponden a la docente.

## Consultas y trabajo académico

Para consultas sobre un entregable, indicar su número y la sección que origina la duda. En problemas técnicos, incluir el mensaje de error, las versiones y los pasos para reproducirlo. Evitar contraseñas, tokens y datos personales en mensajes o capturas.

Explicar las decisiones del equipo, citar las fuentes utilizadas y distinguir los aportes propios del material de terceros. Utilizar datos sintéticos para las demostraciones y pruebas.

## Entorno y documentación

Consultar las [herramientas](../recursos/herramientas.md) y la [preparación del entorno](entorno.md). Registrar las versiones compatibles utilizadas y conservar las dependencias del proyecto.

Mantener Markdown con títulos jerárquicos, enlaces descriptivos y texto alternativo en imágenes. Usar enlaces relativos entre documentos del repositorio del equipo.
